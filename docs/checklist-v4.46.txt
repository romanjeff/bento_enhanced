bento_enhanced v4.46: FM amounts as Mod Matrix destinations, piano-roll lanes on them, FM Env 1 / 2 as sources
(stock 1.6.8) - combined delta checklist on top of v4.44
==============================================================================================================

Kit: flash\bento_enhanced-v4.46, boot label BE4.46 (made by tools\make_kit.py; its SHA256SUMS.txt covers every file).
  01_TEST_FIRMWARE   bento1.bin = the test image on 1.6.8, bento2.bin = stock 1.6.8 Controller
  03_RESTORE_STOCK   stock 1.6.8 (bento1.bin, bento2.bin)
  SHA256SUMS.txt     hashes of every file in the kit
  manifest.json      what the image contains (groups, addresses, every write)
  DEVICE_CHECKLIST.txt  this file (docs\checklist-v4.46.txt)

BE4.46 is the merge of two lanes that were built and checked apart:
  - BE4.45 (branch be445x): FM amounts as Mod Matrix destinations (X1, X2) and piano-roll lanes on them (X3).
    Plan: docs\plan-fm-targets.md. Its own kit (flash\bento_enhanced-v4.45) was never device-checked.
  - The FM Env sources lane (branch be445, labelled 4.46 there): FM Env 1 / FM Env 2 as Mod Matrix sources (S1, S2).
    Plan: docs\feasibility-fm-env-sources.md. Its kit was flash\bento_enhanced-v4.46-envsrc.
Neither lane's device checklist was run, so this one covers both, plus what only the merge makes possible: an FM Env
routed to an FM amount. Release notes: docs\release-notes-v4.46.md. Everything below was measured in the emulator only.
This is a delta on BE4.44: docs\checklist-v4.44.txt still applies in full (nothing unrouted changed: the emulator shows
BE4.44's output and voice state byte for byte with nothing routed). The two BE4.44 alternate kits (mip 1.5, mip off) are
not rebuilt: this release has the release threshold (1.75).

What changed since BE4.44:
  - A Wavetable track's Mod Matrix has three more rows: OSC1: Sub FM (after OSC1: Position), OSC2: FM 1>2 and
    OSC2: Sub FM (after OSC2: Position). 26 rows. The oscillator rows now read "OSC1: ..." / "OSC2: ..." (BE4.44 showed
    "WT1: ..." / "WT2: ..."). The CC column of the new rows is blank.
  - A routing moves the knob: amount 100 % with the source at full moves the knob by the whole travel (0..100 %), then
    the usual depth curve. The knob is where the travel starts; the result is held to 0..100 %. Several routings on one
    row add up. Works on Analog and Wavetable oscillators; with the knob at 0 a routing alone turns FM on.
  - OSC2: Sub FM has no knob (since BE4.43). It plays only while routed, next to FM 1>2.
  - The depth follows the source once per block (2.7 ms), ramped across the block (no zipper).
  - The FM envelope (FM Atk / FM Dec) shapes the routed depth exactly as it shapes the knob's.
  - The piano roll's lane destinations offer OSC1: Sub FM, OSC2: FM 1>2 and OSC2: Sub FM, each on its own oscillator.
  - The Source list of a Wavetable track's Mod Matrix page has two more entries, right after Envelope 2:
        [None], Velocity, Pressure, Envelope 1, Envelope 2, FM Env 1, FM Env 2, LFO 1, LFO 2, Mod Seq, Key, Mod Wheel,
        Macro X, Macro Y, Auto A, Auto B, Auto C, Auto D
    FM Env 1 is OSC1's FM envelope (its FM Atk / FM Dec), FM Env 2 is OSC2's: on an Analog and on a Wavetable oscillator.
    Per voice, restarted at every note, running whenever FM Atk / FM Dec is set (even at FM amount 0). An unset envelope
    (FM Atk 0, FM Dec Inf) gives a constant 1: a fixed offset.
  - FM Env 1 / 2 can be routed to the three FM rows too: the FM depth then follows the FM envelope's value of the same
    block (offline: bit for bit the knob turned to that depth every block).
  - The ANALOG line has a new field x2lost= (FM routings the M7 could not keep; should stay 0).
What to expect that is not a bug:
  - The modulation is block rate: an LFO above about 100 Hz on an FM amount aliases (folds above 187 Hz). Use the FM
    rows' own audio-rate sources (Sub FM, FM 1>2) for audio-rate effects. FM Env moves once per block too.
  - FM Env routed to an Envelope or LFO parameter acts one block late (stock has the same lag between its sources there).
  - seq1..seq4 routed to the same FM row share one slot (stock's rule for every destination): the last one wins.
    Removing either of two such routings silences the other too until the project is reloaded (stock's rule as well).
  - A lane whose routing is edited on the Mod Matrix page to another source (seq1 -> Velocity) keeps playing next to
    the new source until the project is reloaded, even after that routing is set to None. Offline, stock does the same
    on OSC1: Position (section 7 checks it on the device).
  - A Wavetable OSC2's Sub FM starts from 0 even if an old project stored a value for it (an Analog OSC2 starts from it).
    Accepted (Jeff, 2026-11-17): no control on the page sets that value.
  - A voice's first FM Env routing, made mid-note, reads 1 (the unset value) for one block. Kept on purpose.
  - CPU: OSC2: Sub FM routed on the heaviest voice is 5.6..6.4 % over BE4.44's heaviest voice. Accepted as a known
    limit (Jeff, 2026-11-17): it needs all 8 voices of the heaviest Wavetable voice, where voice stealing and glitches
    are normal. With every matrix slot used on 8 tracks and the FM envelopes running, the other two FM rows are up to
    0.24 % over too (the same 8-voice case; recorded for Jeff). Section 8 records both.
  - One step past Auto D in the Source list may show [None] (stock's page reads one past its list too).
  - In the file an FM Env routing is stock's: src="env3" (FM Env 1) or src="lfo3" (FM Env 2); an FM row's routing is
    dest="bento_subfm" / "bento_fm12". Section 9 says what older firmware does with them.
